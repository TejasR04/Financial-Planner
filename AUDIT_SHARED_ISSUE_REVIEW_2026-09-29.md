# Second-pass review of shared audit findings

Two independent Luna Max agents rechecked the [source-based triage](AUDIT_TRIAGE_2026-09-29.md) against the [manual demo audit](audit-2026-09-28/MANUAL_DEMO_AUDIT.md) and the current local source. Both reviews were read-only. This is a code-based assessment of whether a symptom can affect authenticated users, not a test of an authenticated production account or proof that the current Vercel deployment matches this changing checkout.

**Corrected tally:** 11 demo/deployment-specific, 18 shared, and 2 mixed findings (31 total). The prior 12/18/1 headline did not match its own table. F13 is now mixed because the reproduced dollar collision comes from a demo-only response; the shared layout has a narrower, unverified edge-case risk. F29 remains shared because Transactions copy affects normal manual-only users, while its Accounts prompt is confusing only in demo.

| ID | Real-user verdict | Consequences and constraints when fixing it |
| --- | --- | --- |
| F03 | **Mixed.** The demo returns identical canned debt details for distinct accounts; the authenticated endpoint addresses user and account ID. Shared dialog copy still calls credit-card payments a “loan.” | Correct the copy without inferring that production debt records are mixed. If tailoring card fields, retain existing saved principal, term, and payment data until their use is reviewed. |
| F05 | **Confirmed shared.** Debt fields rely on placeholders; filled fields lose visible meaning and some lack accessible names. | Add associated, persistent labels and units. Keep field keys and submitted values; expect a slightly taller dialog and verify keyboard/screen-reader behavior. |
| F06 | **Confirmed shared.** Holdings fields and the asset-class selector have the same label problem. | Label controls without altering holdings values. Preserve API enum values while improving option text. |
| F07 | **Confirmed shared.** Settings renders captions as nearby paragraphs, not associated labels, in Profile and Planning. | Connect labels to their controls; leave saved settings and defaults intact. Some captions becoming clickable is desirable. |
| F12 | **Shared, reproduced at the audited width.** The metrics table gets one-third of the `xl` scenario layout and has horizontal overflow even with two scenarios. | Widen or stack the panel while retaining access to every metric. More width for metrics may shrink the chart or increase page height. Horizontal scrolling itself is an intentional fallback, not missing data. |
| F13 | **Mixed, with no proven ordinary production collision.** Demo sends one full-dollar `illustration` value; normal sensitivity rows use percentages or percentage points. The common 64px value slot could still overflow on unusually large real percentage changes. | Fix the demo row's presentation and make value layout resilient. Do not change sensitivity calculations to solve a display issue. Test unusually large percentages and narrow viewports before assigning production severity. |
| F14 | **Shared at tablet width.** The search label appears at `md` while header controls compete for width, allowing it to wrap. | Use a compact label/icon or earlier breakpoint; retain an accessible name and command-search discoverability. |
| F15 | **Confirmed shared data-access issue.** On mobile, Account, Cost basis, and Gain/loss are hidden; selecting a position opens history, not these details. | Add a compact detail path or expandable row. Showing all columns instead would increase horizontal scrolling; no holdings data or calculation needs migration. |
| F16 | **Shared usability issue, not absent data.** Mobile Amount is offscreen as the last column of a horizontally scrollable transaction table. | Prioritize merchant and amount in the initial view or use mobile rows. Keep Category, account, and type accessible; a card layout may increase row height. |
| F19 | **Confirmed shared presentation issue.** Forms show raw asset-class and transaction-type enum text. | Map friendly display labels while keeping stored and submitted enum values unchanged. Changing enum values would be a compatibility risk. |
| F20 | **Confirmed shared form clarity issue.** APY appears for credit cards and loans, even though debt APR is captured separately. Backend projections and cash recommendations use APY only for depository accounts; this audit found no debt calculation using that APY. | Hide or explain the field by account type, but preserve existing stored APYs on edit. Do not clear depository APY: it affects projections and recommendations. |
| F21 | **Confirmed shared transient state.** Investments initializes with no dashboard and renders empty-account copy before loading completes. | Gate empty copy on loading and error state; loaded financial data remains the same. |
| F22 | **Confirmed shared navigation issue.** Both demo entry and normal login route to Overview; the auth guard drops the requested deep link. | Preserve an internal return path through authentication. Validate that it is a local route so a supplied URL cannot cause an external redirect; handle stale or inaccessible destinations gracefully. |
| F23 | **Shared at narrow widths.** Header title truncates while actions retain width; the 320px audit also saw a clipped action. | Compact or move secondary actions while keeping them discoverable and keyboard accessible. A menu can add a tap. |
| F24 | **Confirmed shared metadata issue.** Most routes inherit the generic root browser title; Settings overrides it. | Add route titles; no stored-data impact. |
| F26 | **Confirmed shared copy defect.** Insights uses plural “opportunities” for count one. | Pluralize by count; no behavioral impact. |
| F27 | **Shared but content-dependent layout issue.** The desktop Positions table can scroll within a two-thirds-width panel, as it did with the audited three positions. | Improve proportions/column wrapping while keeping a scroll fallback for long names or large values. Removing scroll entirely risks clipping real holdings. |
| F29 | **Composite.** Transactions says “connected accounts” although manual accounts are included. Accounts' link-a-bank prompt is appropriate for normal users but impossible to act on in demo. Overview's “all accounts” is accurate. | Make Transactions wording inclusive of manual accounts and make the Accounts prompt demo-aware. Keep the normal bank-link path visible to eligible users. |
| F30 | **Confirmed shared search-promise gap.** Command search promises accounts but indexes only static commands, despite account data being available in the component. | Either add client-side account results or narrow the placeholder. If adding results, keep command results and predictable keyboard ordering; no account schema change is needed. |
| F31 | **Shared, reproduced layout issue.** The 148px allocation donut plus legend and numeric columns can overflow its narrow Overview panel. Legend labels themselves may wrap, so the earlier “non-wrapping legend” description was too broad. | Reflow chart and legend; preserve allocations and their amounts. Expect a taller card or smaller chart. |

The strongest normal-use fixes are F05–F07, F15, F21, F22, and F30. F12, F14, F16, F23, F27, and F31 merit responsive design work, but several are viewport/content-dependent or involve data already reachable by scrolling. F19, F20, F24, F26, and the shared part of F29 are lower-risk clarity fixes. F13 should not be prioritized as a common production crash or calculation defect from the demo screenshot alone.
