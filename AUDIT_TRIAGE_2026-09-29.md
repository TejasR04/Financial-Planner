# Demo audit: which findings affect normal use?

This triages all 31 findings in [the browser audit](audit-2026-09-28/MANUAL_DEMO_AUDIT.md) against the application and backend code on September 29, 2026. The browser audit observed a deployed demo; this review reads code and targeted tests. It does **not** claim that an authenticated production account was tested. The checkout had pre-existing, changing edits during review, so source findings describe the code inspected here, not necessarily the exact Vercel deployment.

The boundary matters: [demo requests](lib/api-transport.ts) are intercepted and answered by [a separate in-memory API](lib/demo-api.ts). Authenticated requests use the backend. The same React screens and components render both modes.

**Result: 11 demo/deployment-specific findings, 18 shared application findings, and 2 mixed findings.** The original priority labels were based on the demo symptom; they should not all be carried over as production priorities. A [second-pass review](AUDIT_SHARED_ISSUE_REVIEW_2026-09-29.md) independently checked the shared findings and the consequences of fixing them for existing users.

| Finding | Classification | Why |
| --- | --- | --- |
| F01 · Accounts totals | **Demo-specific** | Demo seeds credit and loan balances as positive numbers. Accounts sums signed balances and expects liabilities to be negative. The backend normalizes positive manual credit/loan amounts to negative on create and update, and its account API totals liabilities by type. The observed $39,500 gap is twice the $19,750 demo debt total. No evidence here of the same authenticated-account defect. |
| F02 · Position histories fail | **Demo/deployment-specific; source mismatch** | The real [investment history route](backend/app/api/v1/routes/investments.py) exists. The local demo API now has a matching handler that returns one point per sampled position, and the shared chart explicitly explains that one point cannot form a graph. The deployed demo showed a request error instead. Treat that error as a deployed-demo issue and verify its deployed version; a single point is an expected sample-history limitation, not a broken real chart. |
| F03 · Rewards card displays loan values | **Mixed** | The demo liability endpoint returns the same default $18,500/4.5%/84-month/$250 object for every debt account. That cross-account data error is demo-only. The shared [planning dialog](components/financial-details-dialog.tsx) also calls credit-card details a “loan”; that wording affects normal use. |
| F04 · Amount search misses $95 | **Demo-specific** | Demo transaction search filters merchant text only. The real [transaction repository](backend/app/persistence/repositories/transaction_repository.py) explicitly parses numeric search terms and compares absolute transaction amounts. The normal backend supports this search. |
| F05 · Unlabeled debt fields | **Shared** | [FinancialDetailsDialog](components/financial-details-dialog.tsx) renders the same placeholder-based debt fields in either mode. Values lose their visible meaning once populated, and several inputs lack accessible names. |
| F06 · Unlabeled holdings fields | **Shared** | The same dialog renders ticker, quantity, basis, value, asset class, and date with placeholder-only or no labels for normal accounts too. |
| F07 · Settings labels | **Shared** | The shared [SettingsForms](components/settings-forms.tsx) uses nearby paragraph captions instead of associated input labels for the inspected Profile and Planning fields. |
| F08 · 10 pp versus 11.1 pp drift | **Demo-specific** | Demo allocation hard-codes `drift: "0.1"` while deriving the actual equity weight from holdings. The backend [portfolio allocation service](backend/app/services/portfolio_allocation_service.py) computes actual equity weight minus target, and the client formats that returned drift. |
| F09 · Employer suggested as outgoing payment | **Demo-specific** | The demo merchant list includes all transaction merchants. The real `/transactions/merchants` route filters to negative amounts, so the positive Sample employer income would be excluded. |
| F10 · Accounts Sync all fails | **Demo-specific UI gating** | The demo API rejects sync by design. The header sync is disabled in demo, but the shared Accounts button is not. In normal use that button calls the real refresh workflow; having zero linked institutions is not by itself an error because ticker holdings and contributions may still refresh. |
| F11 · Scenario chart extends past retirement | **Demo-specific** | The demo projection generates points until age 95. The real scenario service passes years-to-retirement to its net-worth projection, matching the chart description. |
| F12 · Scenario comparison clips | **Shared** | [ScenarioCompare](components/scenario-compare.tsx) uses the same narrow one-third-width metrics panel, fixed cell padding, and horizontal overflow in both modes. Two normal scenarios can exhibit the same layout. |
| F13 · Sensitivity value overlaps text | **Mixed: reproduced collision is demo-specific; shared edge-case risk** | Demo alone sends an `illustration` row with a full projected dollar balance. The real scenario service sends percentage or percentage-point changes, so the screenshot does not establish an ordinary authenticated failure. The shared [SensitivityAnalysis](components/sensitivity-analysis.tsx) still fixes value width at 64px, and an unusually large real percentage could overflow it. |
| F14 · Search control wraps at tablet width | **Shared** | [Topbar](components/topbar.tsx) uses the same `md` search label and flex layout in both modes. |
| F15 · Mobile positions omit account/basis/gain | **Shared** | The shared [Investments page](app/(app)/investments/page.tsx) hides those columns by breakpoint without a row-detail alternative. |
| F16 · Mobile transaction amounts offscreen | **Shared** | The shared [Transactions page](app/(app)/transactions/page.tsx) uses a wide horizontally scrollable table; amount is the last column. This is a usability issue, not missing data. |
| F17 · Budget pace equals amount spent | **Demo-specific** | Demo returns `forecast: money(spent)` for every category. The real [BudgetService](backend/app/services/budget_service.py) extrapolates spending and pending amounts by elapsed days to month end. |
| F18 · Contradictory reserve recommendation | **Demo-specific** | The demo seeds the recommendation text, $1,200 impact, and 0.9 confidence independently of its balances. The real [RecommendationEngine](backend/app/services/recommendation_engine.py) uses account balances, APYs, and the saved reserve target. This does not validate every real recommendation, only rules out this canned sample contradiction as evidence of a real calculation bug. |
| F19 · Raw enum names in forms | **Shared** | The shared planning dialog emits values such as `fixed_income` directly as select option text. Some transaction type displays may be styled, but the holdings selector issue is real. |
| F20 · APY on credit-card form | **Shared** | The shared [ManualAccountDialog](components/manual-account-dialog.tsx) shows APY for every manual account type. Debt APR is handled separately. |
| F21 · Premature Investments empty state | **Shared** | The shared [Investments page](app/(app)/investments/page.tsx) starts without a dashboard and renders zero-account/empty-state copy before the request settles. Remote latency can expose this in normal use as well. |
| F22 · Deep link returns to Overview after entry | **Shared authentication routing** | Demo toggle and normal login both push `/` in [AuthProvider](lib/auth-context.tsx); neither preserves the original `/investments` path. |
| F23 · Mobile header truncation | **Shared** | The shared Topbar has the same title and action widths in both modes. |
| F24 · Generic browser titles | **Shared** | [Root metadata](app/layout.tsx) sets a generic title. Only Settings defines a route title. |
| F25 · Unformatted narrative amounts | **Demo-specific** | The demo insight text interpolates `toFixed(2)` values. The real [InsightService](backend/app/services/insight_service.py) formats currency with thousands separators. |
| F26 · “1 opportunities” | **Shared** | The plural label in the shared [Insights page](app/(app)/insights/page.tsx) does not handle count one. |
| F27 · Desktop Positions scrollbar | **Shared** | The shared investment table sits in a two-thirds-width panel and uses padded columns. Real holdings with the same column lengths can overflow. |
| F28 · Monte Carlo “Unavailable” | **Demo-specific limitation** | The demo projection returns `success_rate: null`. Normal scenario previews request 1,000 Monte Carlo trials and populate success when the backend returns a result. If a real preview fails, the app still needs a clear error, but the observed sample “Unavailable” does not prove such a failure. |
| F29 · Linked/connected-account wording | **Shared in Transactions; demo-specific in Accounts** | Transactions describes activity across “connected” accounts even for manual-only normal users. The Accounts prompt to link a bank is valid for normal users but misleading in demo because linking is disabled there. Overview's “all accounts” wording is accurate. |
| F30 · Command search cannot find accounts | **Shared** | [CommandPalette](components/command-palette.tsx) advertises accounts in its placeholder but filters only static command labels/groups/keywords. It never indexes the accounts it receives. |
| F31 · Overview allocation clips | **Shared** | The shared [AllocationChart](components/charts/allocation-chart.tsx) fixes the donut at 148px beside a legend with numeric columns inside a narrow panel. Legend labels may wrap, but chart width and number widths can still overflow. The holdings amounts affect text length, while the layout risk is shared. |

The uncounted design notes from the original report also need separating: a neutral demo identity and the September 27/28 sample-date mismatch concern the demo presentation. Missing investment range/account controls and inert investment-account cards are product feature requests, not demonstrated defects. Investment range controls have since appeared for selected positions in the local checkout; that source change was not validated against the deployed demo.

The strongest normal-use work items from this audit are **F05–F07 (form accessibility), F15 (mobile holding details), F21 (loading state), F22 (return path), and F30 (misleading account search)**. F12, F14, F16, F23, F27, and F31 are shared responsive issues, although some are content-dependent or involve an existing horizontal-scroll affordance. The headline financial-number contradictions F01, F08, F17, and F18 should be fixed in demo fixtures/responses, not used as proof that real-account calculations are wrong.

Validation: 12 targeted backend tests for account normalization and portfolio allocation passed. The focused Vitest run could not start because the local sandbox blocked the esbuild child process (`spawn EPERM`). No authenticated production account was used and no application source was changed by this triage.
